Why Use This Assignment?

Most AI literacy training focuses on a single exchange: write a prompt, evaluate the output, verify a claim. This assignment addresses the next problem — the one that emerges when AI-supported work spans more than one session.

AI does not automatically preserve the project state students need. Even when a platform offers memory, projects, custom instructions, or file retrieval, the student still has to know what belongs in the current context and what must be deliberately documented. Without deliberate handoff practices, decisions made in one session disappear before the next. Students re-explain context they already established. AI re-generates options already rejected. The project drifts because its history lives nowhere except in the student's own imperfect recall.

The handoff file is the solution: a compact, structured document created at the end of each AI session that captures what was accomplished, what was decided, what was rejected, and what comes next. In a new chat, the student pastes the handoff file rather than re-explaining everything from scratch. The collaboration resumes from where it left off.

This is not a bureaucratic exercise. It is the practice of treating a human-AI collaboration as a managed project — which is exactly what serious AI-supported work requires. It also supports resource-aware use: good context management means less re-introduction, less correction, and fewer unnecessary exchanges.

The psychology connects directly: external memory, distributed cognition, metacognitive monitoring, and prospective memory are all operating when a student creates a handoff file. Writing the file requires knowing what was decided — which requires having paid attention. The act of writing is itself an encoding event.

If your work cannot survive a new chat, you are not managing the collaboration. You are just having a conversation.

Student Learning Outcomes

By completing this assignment, students will be able to:

  1. Create a structured handoff document that preserves project state across AI sessions.
  2. Identify what information must be explicitly documented versus what AI can reconstruct from general knowledge.
  3. Explain how the handoff file functions as an external memory aid using psychological frameworks.
  4. Demonstrate that AI-supported work can maintain coherence and quality across multiple sessions when managed deliberately.

Student Assignment Sheet

Purpose

Serious work takes more than one sitting. Serious AI-supported work often takes more than one chat. The problem is that AI may not have the specific context you and it created last session — and without documentation, neither will you have the organized, actionable version of it you need.

A handoff file solves this. It is a short, structured document you create at the end of each AI session that captures enough context to resume the work intelligently in a new chat. The goal is not to record everything — it is to record what matters. That judgment is the skill.

Every handoff file should include the following sections. Keep each one brief and specific — this is a working document, not an essay.

Task

Setup — Choose Your Project

Select a psychology learning project that will take genuine effort to complete — not something you can finish in a single sitting. Your instructor will specify the project or allow you to choose from the options below.

Project options:

  • A structured study guide for an upcoming exam, covering three to five major concepts in depth
  • A concept explanation written for a specific audience (a high school student, a skeptical non-psychologist, a future employer)
  • An analysis of a psychological case study using two or three theoretical frameworks
  • A literature-informed argument on a contested psychology question

Session 1 — Begin and Document (30 to 45 minutes)

Open an AI tool and begin your project. Work through genuine back-and-forth — do not accept the first output. Make decisions about content, examples, framing, and structure. Push back on at least one AI suggestion. Verify at least one factual claim.

When you reach a natural stopping point — not when the project is done, but when a phase is genuinely complete — stop the AI work and create your first handoff file using the template above.

Be specific. "Decided to focus on operant conditioning rather than classical conditioning because the case study involves behavioral change over time" is a useful decision record. "Talked about conditioning" is not.

Save the handoff file where you can find it.

Session 2 — Resume Without Recapping (30 to 45 minutes)

Open a completely new chat. Do not re-explain the project. Instead, begin with:

Here is my project handoff file. Please read it carefully, confirm what you understand about the current state of this project, and then we will continue from the next steps listed.

Paste your handoff file. Let AI confirm its understanding. Correct anything it misread. Then continue the work.

Make further decisions. Reject further suggestions. Check further claims. At the end of Session 2, create your second handoff file.

Final Deliverable — Core Version

Submit all of the following:

  1. Your completed or substantially-in-progress project product
  2. Both handoff files (Sessions 1 and 2), complete and unedited
  3. A reflection of 250 to 350 words addressing:
    • What information in the handoff files proved most critical for resuming the work? What could have been cut?
    • How does the handoff file function as an external memory aid? Connect your answer to at least one psychological concept from the course.
    • What habits from this assignment would you carry into future AI-supported work?

If your instructor has assigned the Advanced Version, see Optional Variations for Session 3 instructions and the additional reflection prompt.

Guiding Questions

  • What is the difference between AI "knowing" your project and having your project state in its current context window?
  • Which sections of the handoff template were hardest to fill in honestly — and what does that difficulty tell you about how carefully you were monitoring your own work?
  • If a colleague opened your handoff file and started working on the project without you, what would they be able to do? What would they be missing?
  • What did you learn about your own decisions by writing them down?

AI Use Rules

AI use allowed: Required for Sessions 1 and 2 (and Session 3 if the Advanced Version is assigned). Students may not use AI to write the handoff files, the Session 3 control notes, or the final reflection.

Not allowed: Students may not use AI to reconstruct what was decided in a previous session. The handoff file must be written by the student at the end of each session while the session is still open.

Required disclosure: For each session, I used AI to _____. I decided _____. I rejected _____. I verified _____. My handoff file and reflection are my own work. I am responsible for the final product.

Privacy rule: Do not enter personal, student, client, patient, participant, workplace, family, or otherwise sensitive information into public AI tools.

Verification rule: When you resume from a handoff file, treat AI's restatement of your project as claims to check against the file itself before continuing. Any factual claim that survives into the final product must be verified against course-appropriate sources and recorded in the handoff's sources-checked section.

Resource rule: Use the handoff file instead of re-explaining context from scratch. Resource-aware AI use means providing enough context to work well while avoiding unnecessary back-and-forth, repeated full regenerations, and avoidable rework.

Learning protection rule: The handoff file must be written by the student during the session — not reconstructed afterward. The act of writing it while the session is fresh is part of the learning.

Criteria for Success

Strong work will:

  • produce handoff files that are specific, honest, and genuinely actionable — not vague summaries
  • document real decisions, real rejections, and real constraints — not just topics covered
  • demonstrate that Session 2 resumed from the handoff without unnecessary re-explanation
  • (Advanced Version only) use the Session 3 control notes to identify what changed when the handoff was absent
  • connect the handoff file to a psychological concept with genuine understanding, not surface labeling
  • show through the final product that sustained, coherent AI collaboration is possible when managed deliberately

Instructor Notes

Why this assignment is different from other AI documentation assignments: Most AI documentation exercises ask students to record what AI said and whether it was right. The handoff file asks students to record what they decided — and why. The distinction is significant. Decisions, rejections, and constraints are inherently human contributions. Writing them down makes that contribution visible to students who may not have noticed they were making it.

On the handoff file template: The template is meant to be used, not admired. Encourage students to copy it into a plain text document at the start of each session and fill it in before closing. The constraint that it must be written while the session is open — not reconstructed afterward — is essential. Students who wait will find they cannot accurately reconstruct their own decisions. That frustration is itself informative.

What Session 3 typically reveals (Advanced Version): The control condition (Session 3, no handoff) typically produces two kinds of problems. The first is re-generation: AI proposes options or framings the student already evaluated and rejected, because there is no record of the rejection. The second is constraint loss: parameters the student had established (the audience, the scope, the style, the conceptual frame) are absent from the new context, and AI defaults to something generic. Students who experience these concretely understand what the handoff files were actually doing. Recommended for Research Methods and Capstone courses where sustained AI-supported work is a regular expectation.

The resource-aware dividend: A well-constructed handoff file can reduce unnecessary context re-introduction and correction across sessions. Do not frame this as exact carbon accounting. Frame it as a professional habit: preserve project state, avoid rework, and use AI with enough context to be useful without wasting effort or output.

On the psychological connection in the reflection: The most common connections students make:

  • External memory — the handoff file offloads memory from the student's own working memory to a stable external record
  • Distributed cognition — some researchers propose that the student, the AI, and the handoff file together constitute a distributed cognitive system in Hutchins's sense; no single element holds the whole project. Whether an AI session qualifies as a genuine node in such a system is actively debated — students who engage that debate are doing the assignment at a higher level
  • Metacognitive monitoring — the act of writing the handoff requires the student to monitor their own session in real time, noticing decisions as they happen
  • Prospective memory — the handoff is a prospective memory aid, encoding what needs to happen next in a form that survives the gap between sessions

All four are correct and worth validating. Push students toward the most specific connection they can make.

Pairing with Session Reset: If students have already completed the Session Reset, the retrospective handoff document they created there is their entry point for this assignment. The two assignments are designed to run in sequence: Session Reset creates the felt problem (work is lost when the chat closes); the Handoff File Assignment teaches the solution. If running both, consider assigning them in the same week.

Optional Variations

  • Advanced Version — The Control Condition: After completing Sessions 1 and 2, students complete a third session without the handoff file. Open a new chat, describe the project briefly from memory, and ask AI to help continue. Work for 15 to 20 minutes. Note what happens: Does AI re-generate options already rejected? Does it miss constraints already established? After the session, document what was different — better or worse — compared to Sessions 1 and 2. Add a fourth reflection prompt: What did this session reveal about what the handoff files were actually doing? Recommended for Research Methods, Capstone, or any course where students will do sustained AI-supported work across the semester.
  • Minimal template version: Use the minimal handoff template for students' first exposure. Switch to the full template for Session 2 once the habit is established.
  • Group handoff: Teams complete the project collaboratively. Each team member creates the handoff at the end of their session; the next team member resumes from it. This introduces coordination and the challenge of documenting decisions made by more than one person.
  • Instructor-assigned project: Specify the project content to match the current unit. The handoff file structure works with any psychology task.
  • Template refinement: After completing the assignment, students revise the template based on what they found most and least useful. Submit the revised template as part of the reflection. This turns the assignment into a design exercise.
